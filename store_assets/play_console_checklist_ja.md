## 1. リリース用ビルド(AAB)

CI は現状 APK しか作っておらず、しかも署名鍵を持っていないため debug 署名のままになる。
Play に上げる AAB は次のどちらかで作る。

- A. 手元の PC(Android SDK あり)で `android/key.properties` を置いて `flutter build appbundle --release`
- B. CI に GitHub Secrets として鍵を登録し、CI で署名済み AAB を作る(鍵を base64 で Secret に入れ、ビルド時に復元する)

B の方が「毎回同じ手順で作れる」「PC に環境が要らない」ので、こちらを推奨。

## 2. Play Console でアプリを作成

- アプリ名: 手もとメモ

- アプリ / ゲーム: アプリ

## 3. アプリの署名(Play App Signing)

- 「Play アプリ署名を使用する」を有効にする(推奨。アップロード鍵を紛失しても Google 側でリセットできる)
- 最初のアップロード時に使った鍵が「アップロード鍵」として登録される。以後は必ず同じ鍵(`upload-keystore.jks`)で署名する。

## 4. 内部テストで先に配布する

いきなり製品版ではなく「内部テスト」トラックに AAB を上げ、自分の端末に Play 経由でインストールして確認する。
アプリ内購入のテストもこのトラックで行う(下記 6 参照)。

### コンテンツのレーティング(IARC アンケート)

### ターゲット ユーザーとコンテンツ

- 対象年齢: 18歳以上(子ども向けではない)。広告を出すアプリは子ども向けにすると制約が増えるため、子ども向けにはしない。

### ニュースアプリ / 新型コロナ関連 / 政府機関 / 金融 / 医療

- すべて「該当しない」

### データ セーフティ

このアプリで端末外に出るのは **AdMob SDK が広告配信のために扱うデータだけ**。メモ・録音・写真・動画・文字起こし結果は端末内で完結する(端末内処理は Play の定義上「収集」に当たらない)。バックアップは利用者が自分で保存先を選んで書き出すものなので「収集」に当たらない。

記入の目安:

| 質問 | 回答 |
| --- | --- |
| データを収集または共有するか | はい(AdMob SDK 経由) |
| 収集するデータは転送時に暗号化されるか | はい |
| ユーザーがデータ削除をリクエストできる仕組みがあるか | いいえ(アカウントが無く、開発者側に個人データを持たないため) |

収集・共有するデータの種類(AdMob SDK 分):

- 「デバイスまたはその他の ID」 → 広告 ID。目的: 広告またはマーケティング。共有: あり(Google)。
- 「アプリのアクティビティ」 → アプリ内のインタラクション(広告の表示・タップ)。目的: 広告またはマーケティング。
- 「アプリの情報とパフォーマンス」 → 診断情報(AdMob SDK 分)。目的: 分析。

※ AdMob SDK が収集するデータの正確な一覧は時期によって変わるため、記入前に AdMob ヘルプの「Google Play のデータ セーフティ」に関する記事で最新の案内を確認すること。

### 公開対象の国・地域

- 日本のみにするか、全世界にするかを決める。
- **全世界(EU/英国を含む)で公開する場合**、AdMob の広告を出すには GDPR の同意取得(UMP SDK による同意メッセージ)の実装が実質必須。現状のアプリには入っていないので、その場合は実装してから公開する。日本のみなら不要。

## 6. アプリ内アイテム(課金)の登録

Play Console → 収益化 → アプリ内アイテム。**アプリを一度どれかのトラックにアップロードしてからでないと作成できない。**

| 商品 ID(コードと一致させること) | 種類 | 表示名(案) | 説明(案) |
| --- | --- | --- | --- |
| `remove_ads_lifetime` | アプリ内アイテム(一回限りの購入 = 非消費型) | 広告を完全に削除 | バナー広告を永久に非表示にします。一度の購入で有効です。 |
| `premium_themes_pack` | アプリ内アイテム(一回限りの購入 = 非消費型) | テーマパック | 追加のカラーテーマをすべて解放します。一度の購入で有効です。 |

- 価格は任意で決める。
- 作成後、「有効」にしないとアプリ側の `queryProductDetails` に出てこない。
- テスト購入: 設定 → ライセンス テスト に自分の Google アカウントを追加すると、内部テスト版で課金されずに購入フローを確認できる。
- 購入の署名検証(偽装対策)は未実装。登録後、収益化のセットアップ → ライセンス にある「Base64 エンコードされた RSA 公開鍵」を使って実装する(別途作業)。

## 8. 公開後

- クラッシュ・ANR は Play Console → 品質 → Android vitals で確認する(アプリ側にクラッシュレポート SDK は入れていない方針)。
- 問題が出たらバージョン(`pubspec.yaml` の `version: 1.0.0+1`)を上げて再提出する。`+1` の部分(versionCode)は毎回必ず増やす。
