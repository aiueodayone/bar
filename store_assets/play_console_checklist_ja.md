## 1. リリース用ビルド(AAB)の署名を CI に設定する

CI(`.github/workflows/build-apk.yml` の build ジョブ)は、GitHub Secrets に鍵があれば署名済み AAB を、無ければ debug 署名の AAB を `memo-app-aab` として出す。
新規アプリは APK ではなく AAB での提出が必須なので、公開前に次の 4 つを登録する。

GitHub のリポジトリ → Settings → Secrets and variables → Actions → New repository secret:

| Secret 名 | 値 |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | `upload-keystore.jks` を base64 にした文字列(改行なし)。Mac: `base64 -i upload-keystore.jks \| tr -d '\n'` / Linux: `base64 -w0 upload-keystore.jks` / Windows PowerShell: `[Convert]::ToBase64String([IO.File]::ReadAllBytes("upload-keystore.jks"))` |
| `ANDROID_KEYSTORE_PASSWORD` | `keystore-info.txt` の storePassword |
| `ANDROID_KEY_PASSWORD` | `keystore-info.txt` の keyPassword(PKCS12 形式なので storePassword と同じ値) |
| `ANDROID_KEY_ALIAS` | `upload` |

登録後に CI を一度回し(何かを push するか、Actions 画面から "Run workflow")、成果物 `memo-app-aab` をダウンロードする。
ログの "Restore upload keystore from secrets" ステップに "Release signing configured from secrets." と出ていれば署名済み。

※ 実機に直接入れる用の `memo-app-apk` は従来どおり debug 署名のまま(署名を変えると、入れ替え時に一度アンインストールが必要になるため)。

- 「Play アプリ署名を使用する」を有効にする(推奨。アップロード鍵を紛失しても Google 側でリセットできる)

## 5. アプリのコンテンツ(ポリシー関連の申告)

Play Console → ポリシー → アプリのコンテンツ。すべて記入しないと公開できない。

### プライバシーポリシー

- URL: `https://aiueodayone.github.io/bar/`

### 広告

- 「はい、広告が含まれています」

### アプリのアクセス権

- 「すべての機能が特別なアクセス権なしで利用可能」(ログイン等は無い)

### コンテンツのレーティング(IARC アンケート)

- カテゴリ: ユーティリティ / 生産性
- 暴力・性的・薬物・ギャンブル等: すべて「いいえ」
- ユーザー同士の交流・ユーザー生成コンテンツの共有: 「いいえ」(メモは端末内のみ。共有は OS の共有機能で利用者が自分で行うだけ)

### ターゲット ユーザーとコンテンツ

- 対象年齢: 18歳以上(子ども向けではない)。広告を出すアプリは子ども向けにすると制約が増えるため、子ども向けにはしない。

### ニュースアプリ / 新型コロナ関連 / 政府機関 / 金融 / 医療

- すべて「該当しない」

### データ セーフティ

このアプリで端末外に出るのは **AdMob SDK が広告配信のために扱うデータだけ**。メモ・録音・写真・動画・文字起こし結果は端末内で完結する(端末内処理は Play の定義上「収集」に当たらない)。バックアップは利用者が自分で保存先を選んで書き出すものなので「収集」に当たらない。

記入の目安:

| 質問 | 回答 |
| --- | --- |
| データを収集または共有するか | はい(AdMob SDK 経由) |
| 収集するデータは転送時に暗号化されるか | はい |
| ユーザーがデータ削除をリクエストできる仕組みがあるか | いいえ(アカウントが無く、開発者側に個人データを持たないため) |

収集・共有するデータの種類(AdMob SDK 分):

- 「デバイスまたはその他の ID」 → 広告 ID。目的: 広告またはマーケティング。共有: あり(Google)。
- 「アプリのアクティビティ」 → アプリ内のインタラクション(広告の表示・タップ)。目的: 広告またはマーケティング。
- 「アプリの情報とパフォーマンス」 → 診断情報(AdMob SDK 分)。目的: 分析。

※ AdMob SDK が収集するデータの正確な一覧は時期によって変わるため、記入前に AdMob ヘルプの「Google Play のデータ セーフティ」に関する記事で最新の案内を確認すること。

### 公開対象の国・地域

- 全世界で公開する前提。EU/英国向けの GDPR 同意画面(UMP)はアプリに実装済み。
- **AdMob 管理画面での作業が必要**: AdMob → プライバシーとメッセージ → 「GDPR」でこのアプリ向けの同意メッセージを作成して公開する。これが無いと、同意が必要な地域では同意画面が出せず広告が表示されない(アプリ自体は普通に使える)。
- 同意が不要な地域(日本など)では何も表示されず、従来どおり広告が出る。
- 動作確認したい場合: AdMob の同意メッセージ設定でテストデバイスを登録し、地域を EEA に偽装して確認できる(AdMob ヘルプ「同意メッセージのテスト」参照)。

## 6. アプリ内アイテム(課金)の登録

Play Console → 収益化 → アプリ内アイテム。**アプリを一度どれかのトラックにアップロードしてからでないと作成できない。**

| 商品 ID(コードと一致させること) | 種類 | 表示名(案) | 説明(案) |
| --- | --- | --- | --- |
| `remove_ads_lifetime` | アプリ内アイテム(一回限りの購入 = 非消費型) | 広告を完全に削除 | バナー広告を永久に非表示にします。一度の購入で有効です。 |
| `premium_themes_pack` | アプリ内アイテム(一回限りの購入 = 非消費型) | テーマパック | 追加のカラーテーマをすべて解放します。一度の購入で有効です。 |

- 価格は任意で決める。
- 作成後、「有効」にしないとアプリ側の `queryProductDetails` に出てこない。
- テスト購入: 設定 → ライセンス テスト に自分の Google アカウントを追加すると、内部テスト版で課金されずに購入フローを確認できる。
- 購入の署名検証(偽装対策)は未実装。登録後、収益化のセットアップ → ライセンス にある「Base64 エンコードされた RSA 公開鍵」を使って実装する(別途作業)。

## 8. 公開後

- クラッシュ・ANR は Play Console → 品質 → Android vitals で確認する(アプリ側にクラッシュレポート SDK は入れていない方針)。
- 問題が出たらバージョン(`pubspec.yaml` の `version: 1.0.0+1`)を上げて再提出する。`+1` の部分(versionCode)は毎回必ず増やす。
